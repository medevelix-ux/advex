# ADVEX: пилот главной страницы

Публикуются все 27 страниц. Контент главной, отдельные CSS/JS, оптимизация
изображений и Netlify Forms подключены к главной на AZ/RU/EN.
Header и Footer редактируются отдельно и применяются ко всем страницам.
На 24 внутренних страницах дополнительно редактируются SEO title и description;
основное содержимое и поведение внутренних страниц сохранены из исходных макетов.

## Сборка и локальная проверка

Нужен Node.js 22 или новее.

```sh
npm install
npm run build
npm run preview
```

Откройте http://127.0.0.1:4173/ru/. Исходные index.html сохранены как база;
результат сборки и версия для публикации находятся в dist/.
Локальный сервер намеренно отвечает 503 на отправку формы: он не имитирует
доставку письма. Настоящие заявки принимает Netlify после публикации.

`npm test` проверяет контент, HTML, формы, общие блоки, сохранность содержимого внутренних страниц и
размеры изображений. Для браузерных проверок установите Playwright
(`npm install --no-save playwright`, `npx playwright install chromium`),
запустите preview в отдельном терминале и повторите `npm test`.
Браузерные тесты подменяют ответы формы и не отправляют реальные письма.

## Netlify

1. Подключите репозиторий `medevelix-ux/advex`, ветку `main`.
2. Настройки берутся из netlify.toml: build `npm run build`, publish `dist`.
3. В Forms включите **Enable form detection**, затем запустите публикацию.
4. Должны появиться шесть форм: `home-az-lead`, `home-az-quote`,
   `home-ru-lead`, `home-ru-quote`, `home-en-lead`, `home-en-quote`.
5. Добавьте email-уведомление о новых заявках для этих форм на свой тестовый
   адрес. Один адрес можно назначить для всех форм.
6. Отправьте заявку и запрос расчёта с вложением с опубликованного сайта.
   Проверьте Netlify Forms (включая Spam) и получение уведомления на почте.

Обе формы используют обычный POST, работают и без JavaScript. JS добавляет
обработку ожидания/ошибок и список выбранного оборудования. Название формы,
язык, ID заявки и оборудование передаются скрытыми полями. Защита: honeypot и
фильтрация Netlify. Файл — до 7 МБ (у Netlify весь запрос ограничен 8 МБ);
уведомление Netlify может содержать ссылку на загруженный файл.
Двойной клик блокируется в интерфейсе; Netlify Forms не обещает идемпотентность
повторной отправки после сетевого таймаута.

## Pages CMS

1. Войдите на https://app.pagescms.org через GitHub.
2. Разрешите GitHub App доступ только к нужному репозиторию.
3. Выберите `medevelix-ux/advex`, ветку `main`.
4. Откройте «Главная страница» и выберите «Русская версия»,
   «Азербайджанская версия» или «Английская версия».

`.pages.yml` записан в JSON-синтаксисе, который является допустимым YAML.
Меню редактора использует вложенные группы Pages CMS:

```text
Главная страница → Русская / Азербайджанская / Английская версия
Услуги → Изготовление стендов / Модели на выставку → три языка
Каталог оборудования → Каталог стендов / Аренда оборудования → три языка
Наши проекты → три языка
Информационные страницы → О компании / Контакты / Доставка и оплата → три языка
Общие настройки (Header / Footer)
  Header — шапка сайта → три языка
  Footer — подвал сайта → три языка
  Клиенты и партнёры → общий список логотипов и подписи на трёх языках
```

Главная разделена на SEO и восемь групп: «Первый экран», «Всё для вашего
участия в выставке», «Кейсы», «От чистого листа до готового стенда»,
«Детали, которые дополняют пространство», «О компании», «Клиенты и партнёры»,
«FAQ». Остальные существующие секции и формы сохранены в группе
«Дополнительные секции и формы». Это стандартные группы полей Object;
переключение вкладок из концептуального скриншота штатно не настраивается.

В Header названия и адреса меню общие для компьютерной и мобильной версии.
Переключатель языка автоматически сохраняет текущую страницу. В Footer
отдельно редактируются тексты, колонки ссылок, адрес, телефон и email.
Правка Header/Footer одного языка применяется ко всем девяти страницам
этого языка при следующей сборке.

Логотипы клиентов хранятся один раз в `content/shared/clients.json`.
Их можно добавлять, удалять и переставлять; заголовок и alt задаются по языкам.
В редакторе главной есть переключатель видимости этого общего блока.
Сейчас в исходном дизайне блок размещён на трёх главных страницах;
внутренние страницы автоматически его не получают. Общий шаблон готов
к подключению там, где блок понадобится.

Тексты не принимают HTML: ввод экранируется,
существующая разметка и переносы заголовков остаются в шаблоне.
В «Кейсы» и «FAQ» можно добавлять, удалять и переставлять карточки/вопросы.
Загрузка новых изображений ограничена `img/home-uploads/`, поэтому через
медиатеку CMS нельзя удалить исходные общие изображения других страниц.

Контент хранится в `content/home/`, `content/shared/` и `content/pages/`.
При сохранении Pages CMS создаёт коммит. Git-интеграция Netlify запускает
сборку: готовый HTML уже содержит новые тексты/SEO, изображения преобразуются
в WebP с несколькими размерами. Новые загрузки обрабатываются автоматически.
Для повторной публикации без изменения данных: Netlify → проект → Deploys →
Trigger deploy → Deploy site. После изменения `.pages.yml` обновите вкладку
Pages CMS и заново выберите репозиторий/ветку при необходимости.

`node scripts/check-cms.mjs` временно меняет данные, собирает сайт, проверяет
применение Header/Footer на девяти страницах, клиентов на трёх языках,
SEO внутренней страницы и изменения главной, затем восстанавливает данные
и проверяет точное восстановление всех 27 результатов сборки.

### Приёмка реальной интеграции

- В Pages CMS изменить SEO title, description и текст первого экрана.
- Заменить изображение первого экрана.
- Добавить пятый проект в блок проектов на главной.
- Дождаться успешной публикации в Netlify.
- Проверить эти изменения на сайте и в исходном HTML без выполнения JS.
- Проверить отображение на телефоне, обе формы и получение писем.
- Вернуть тестовые правки через Pages CMS и проверить повторную публикацию.

## Границы пилота

- Тестовая публикация закрыта от индексации через robots.txt и X-Robots-Tag.
  Это не ограничение доступа: ссылка остаётся публичной.
- Canonical/hreflang пока указывают на будущий основной домен advex.az.
- Неразработанные категории в общих Header/Footer и на главной ведут на
  существующий общий каталог. В содержимом внутренних страниц ссылки
  пока остаются исходными.
- Политика конфиденциальности и демо-отзывы требуют подготовки перед приёмом
  реальных клиентских заявок. В пилоте используйте тестовые данные.
- Выбор оборудования сохраняется для главной. Интеграция с внутренней
  страницей аренды — следующий этап.

Не запускайте `scripts/import-home.py` и `scripts/migrate-cms-blocks.py`
повторно: это одноразовые миграции, а не команды сборки. В обычной работе
нужен только `npm run build`.
